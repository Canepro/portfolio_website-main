# Portfolio design system

This system records the portfolio's existing editorial layout, IBM Plex typography,
sky accent, charcoal canvas, and warm-paper light theme. Preserve its content,
page structure, evidence illustrations, and restrained use of chrome.

Extracted from the existing site at baseline `83a74fccd28d139b5b705622731db4f9b53571d8`,
then reconciled with the local components and rendered light and dark themes.

## Colors and tokens

`src/styles/globals.css` is the single foundation and theme source.
HSL channel values support the existing Tailwind 3 utilities; their comments
record the equivalent brand hex colors. `:root` supplies dark defaults;
`html.light-theme` overrides theme roles. The existing theme toggle and saved
`theme` preference remain the consumers.

| Role                | shadcn token                                                 | Existing portfolio alias                     |
| ------------------- | ------------------------------------------------------------ | -------------------------------------------- |
| Canvas              | `--background`                                               | `--color-bg-primary`                         |
| Surface             | `--surface`, `--card`, `--popover`, `--secondary`, `--muted` | `--color-bg-secondary`                       |
| Ink                 | `--foreground` and surface foregrounds                       | `--color-text-primary`                       |
| Secondary ink       | `--muted-foreground`                                         | `--color-text-secondary`                     |
| Sky action or link  | `--primary`, `--ring`                                        | `--color-accent`, `--color-accent-secondary` |
| Text on action      | `--primary-foreground`                                       | Use the button variant                       |
| Quiet hover surface | `--accent` / `--accent-foreground`                           | Separate from the sky action color           |
| Structural rule     | `--border`                                                   | `--color-border`                             |
| Control boundary    | `--input`                                                    | Use `border-input`                           |
| Error               | `--destructive` / `--destructive-foreground`                 | Use semantic utilities                       |

Decorative rules use white at 10% on dark and black at 10% on light. They are
structural separators, not control boundaries. Inputs and selects use the stronger
input token so their edges reach 3:1 against the canvas. Quiet cards preserve
the existing translucent fills: white 5% / 8% on dark, black 3% / 6% on light
(rest / hover). Text inherits the corresponding ink tokens.

Primary and accent buttons use sky fill with charcoal text on dark and warm-paper
text on light. Hover reduces action fill opacity to 90%; links retain solid color and
thicken their underline on hover. Ghost and outline hover states use the quiet surface
with normal ink. Focus uses the sky token: a 2px outline with 4px offset for
plain controls and links, or the primitive's 2px ring. Disabled controls retain
the existing 50% opacity and disabled semantics. Error text uses the theme error
token, rather than a fixed red utility.

## Typography

Use the locally bundled IBM Plex Sans faces at weights 300, 400, 500, 600, and 700. IBM Plex Mono uses 400, 500, and 600 for dates, technical labels, and code.
`next/font/local` supplies `--font-sans` and `--font-mono`; no font substitution
or remote font request is required.

The Tailwind type scale reads these CSS tokens. Sizes preserve the existing scale.

| Utility / token             | Size | Default line height | Use                              |
| --------------------------- | ---- | ------------------- | -------------------------------- |
| `text-xs` / `--type-xs`     | 12px | 16px                | Evidence captions, compact chips |
| `text-sm` / `--type-sm`     | 14px | 20px                | Dates, navigation, controls      |
| `text-base` / `--type-base` | 16px | 24px                | Body text                        |
| `text-lg` / `--type-lg`     | 18px | 28px                | Intro and desktop reading text   |
| `text-xl` / `--type-xl`     | 20px | 28px                | Long-form h3                     |
| `text-2xl` / `--type-2xl`   | 24px | 32px                | Long-form h2, mobile titles      |
| `text-3xl` / `--type-3xl`   | 30px | 36px                | Section headings                 |
| `text-4xl` / `--type-4xl`   | 36px | 40px                | Page titles                      |
| `text-5xl` / `--type-5xl`   | 48px | 1                   | Larger titles                    |
| `text-6xl` / `--type-6xl`   | 60px | 1                   | Desktop homepage title           |

Page and section headings keep their current medium weight and tight tracking;
long-form headings use semibold. `proseClasses` owns shared Markdown and MDX
reading treatment: 16px mobile, 18px desktop, `--leading-prose: 2rem` (32px)
line height. MDX paragraphs and lists use that same line height. Inline and
fenced code use Mono at 14px. Links remain underlined with 4px underline offset.

## Layout and spacing

Keep the existing Tailwind spacing rhythm from the frontmatter. PageShell owns
page gutters and widths; ContentSection owns homepage sections. Keep the desktop
split hero and project rows, stacked mobile layout, article reading width, and
existing heading spacing. Structural rules separate work and writing entries.
Use shared layout components before adding local wrappers.

## Shape and elevation

Use 4px small accents, 6px compact controls and chips, 8px standard corners,
12px inputs and inset links, and 16px cards. Pill badges retain full rounding.
Tailwind radius utilities map to the matching `--radius-*` token.

| Tier          | Dark shadow                 | Light shadow                 | Use                             |
| ------------- | --------------------------- | ---------------------------- | ------------------------------- |
| `--shadow-sm` | `0 2px 10px rgba(0,0,0,.3)` | `0 2px 10px rgba(0,0,0,.1)`  | Inputs, buttons, article images |
| `--shadow-md` | `0 4px 20px rgba(0,0,0,.4)` | `0 4px 20px rgba(0,0,0,.15)` | Raised supporting surfaces      |
| `--shadow-lg` | `0 8px 30px rgba(0,0,0,.5)` | `0 8px 30px rgba(0,0,0,.2)`  | Mobile navigation overlay       |

Tailwind `shadow`, `shadow-sm`, `shadow-md`, and `shadow-lg` consume those tokens.
Most editorial sections use a rule and spacing rather than elevation.

## Component recipes

- Button: retain CVA variants and sizes (36px default/icon, 32px small, 40px large).
  Default and accent share the action pair. Outline uses the input edge; ghost
  uses the quiet surface on hover. Keep disabled and keyboard focus behavior.
- Input and Textarea: 40px input height, 144px minimum textarea height, 12px
  radius, canvas fill, input boundary, secondary-ink placeholder, sky focus ring.
- Badge: retain existing variants; primary and destructive hover fills use 90%
  opacity. Tech chips use quiet card fill and secondary ink.
- Card and inset links: retain existing geometry and hover fills. No new card
  wrappers around editorial sections.
- Blog filter: native labeled select, canvas fill and input boundary. Retain its
  filtering behavior and result announcement.
- Long-form content: shared prose, horizontally scrollable code and tables,
  ink headings and code, sky links, quiet blockquote rule.

## Do's and don'ts

Keep both themes readable, preserve underlines, respect reduced motion, and use
semantic tokens for new states. Inspect the real page after token changes.
Keep analytics and contact behavior intact. Leave blog drafts #99 and #100 alone.

Do not introduce a preset, change brand fonts or the page structure, add neon or
purple/cyan haze, add decorative glass chrome, or turn every entry into a card.
Do not use the sky action color as a surface token with white text in dark mode.
Do not use faint structural rules for controls that need a visible boundary.
